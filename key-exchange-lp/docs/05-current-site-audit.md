## 2. 活かせる資産
- **WordPressがすでに動いている** → サーバー移転は不要。デザインと構成の作り替えだけで済む
- **作業事例が約39件ある** → 一次情報として最も価値の高い資産。消さずに活かす
- **「中間手数料なし（自社スタッフ）」** → 仲介型の大手サイトとの明確な差別化ポイント。新LPでも打ち出す
- 「作業前に料金説明」「見積後キャンセル可」 → 新LPの「料金が後から増えない3つのルール」とそのままつながる

## 3. 直すべき点（優先度順）

| 優先 | 問題 | 影響 | 対応 |

| 高 | **料金が一切載っていない** | 緊急の人が比較で離脱する。広告の品質評価も上がりにくい | 料金表を新設（ヒアリング待ち） |
| 高 | **事例記事のタイトルが全部同じ**（「カギトラブル解決事例をご紹介します！」） | 検索結果で区別できず、ほぼ評価されない | 「江東区東砂で鍵紛失による玄関の鍵開け｜鍵マッハ24」の形式に既存39件もリネーム |

| 中 | PC用とスマホ用で同じ内容を2回ずつ書いて出し分けている | 内容の重複、修正漏れの原因 | 1つのレスポンシブなHTMLに統合（新LPは統合済み） |

## 4. 移行方針

**サーバー・ドメイン・WordPressはそのまま。テーマを「Lightningの子テーマ」として作り替える。**

- 子テーマにする理由：既存の投稿・固定ページ・プラグイン・フォームを壊さず、デザインだけ差し替えられる。親テーマ（Lightning）のアップデートも引き続き受けられる
- トップページ：子テーマに `front-page.php` を作り、`src/index.html` の構成をそのまま移植
- 投稿（コラム・事例）：子テーマのテンプレートで、結論ボックス・監修者・記事内CTA・構造化データを自動で出す
- 既存の作業事例39件：URLはそのまま、タイトルと分類（エリア・作業内容）だけ整える
- 作業は**ステージング環境（テスト用のコピー）で行い、確認後に本番へ反映**する。エックスサーバー等には管理画面からステージングを作る機能がある
